# Demo 腳本 — 餐飲點餐快手(5 分鐘)

> 對象:提案評審委員 / 潛在客戶
> 時間:**5 分鐘**(開場 30s + 場景一 60s + 場景二 60s + 場景三 60s + 場景四 60s + 結尾 30s)
> 設備:2 個螢幕(平板跑 KIOSK、筆電跑門市後台)、1 隻手機(已開 mobile-app)
> 事前準備:`./scripts/start-all.sh` 已跑、三個 URL 通暢、兩個 demo 帳號已 seed

---

## 開場(30 秒)

### 痛點

- **門市尖峰時段**,櫃台排隊 **15 分鐘**,顧客等待焦慮
- 顧客**不知道餐點何時好**,反覆詢問櫃台 → 增加櫃台工作負荷
- **會員回購率低**,缺乏有效的優惠與點數機制

### 解決方案

> **KIOSK 平板 + 手機 APP 即時追蹤 + 會員回訪**,一站解決點餐、取餐、回購三大問題。

### 我們今天要看

1. KIOSK 自助點餐(平板)
2. 手機掃 QR 即時追蹤(手機)
3. 門市後台推進出餐(筆電)
4. VIP 會員折扣 + 點數累積(平板)

## 場景一:KIOSK 自助點餐(60 秒)

> **目標**:展示 2 分鐘內完成點餐 + 結帳 + 取得取餐號

### 步驟

1. **平板顯示首頁**,7 個分類入口(推薦餐點 / 人氣精選 / 主餐 / 配餐 / 飲品 / 甜點 / 會員專區)
2. 點「**推薦餐點**」:3 張大卡(經典脆雞 $149 / 花生牛肉堡餐 $179 / 泰式椒麻雞餐 $169)+ 4 張小卡(塔香脆雞 / 可樂 / 薯條 / 雞塊)
3. 點「**經典脆雞**」→ 底部展開客製化面板(主食 / 醬料 / 加購 三群組 chips)
4. 選「**白飯 + 醬油 + 薯條 +$30**」→ 加入購物車
5. 加入「**可樂(中)$30**」、「**塔香脆雞 $149**」
6. 右側購物車顯示品項清單 + 小計 **$209**
7. 點「**前往結帳**」→ 輸入電話 `0912345678` → 驗證碼 `1234` → 登入 VIP
8. 看到 **VIP10 coupon** → 確認結帳
9. 完成畫面:**取餐號 A002** 大字 + 訂單編號 `SD-20260824-0002` + QR code(顧客手機掃)

### 關鍵 Demo 賣點

- ✅ 大按鈕(≥ 48px)、直式版面,**單頁不切換 routing**
- ✅ 底部客製化面板**不擋右側購物車**
- ✅ chips 視覺化,所見即所選
- ✅ 完成頁取餐號 **120px 橘底白字**,視覺記憶點強

## 場景二:手機掃 QR 追蹤(60 秒)

> **目標**:展示顧客如何即時掌握出餐進度

### 步驟

1. 顧客拿出手機掃 KIOSK 上的 QR(內容 `{WEB}/track/SD-20260824-0002`)
2. APP 開啟追蹤頁(若無 APP,引導「加入主畫面」→ **PWA**)
3. 顯示:**取餐號 A002**(橘底白字 96px)
4. 顯示:**預計 12:24 可取餐** + 倒數計時(每分鐘更新)
5. 顯示:**進度時間軸**
   - 已接單 ✓(綠勾,時間 12:21)
   - 製作中 →(橘色高亮 + 脈動動畫,時間 12:24)
   - 已完成 ○(灰色,待觸發)
6. 顯示:**VIP 會員獨享 9 折** CTA(橘→金漸層)

### 關鍵 Demo 賣點

- ✅ **PWA 不用裝 APP**,iOS / Android 通吃
- ✅ 取餐號超大、預估時間 + 倒數 — **降低等待體感焦慮**
- ✅ VIP CTA 把優惠券放在最顯眼處 — **回購驅動**

## 場景三:門市推進狀態(60 秒)

> **目標**:展示「門市人員按一個按鈕,顧客手機即時更新」的魔法

### 步驟

1. 門市人員開 `/admin` 後台(`http://localhost:5173/admin`)
2. 看到所有 active 訂單清單(A001 / A002 / A003)
3. 點「**下一階段**」推進 A002 → **PREPARING**(進度 30%)
4. **手機畫面同步**:進度從 10% → **30%**,階段 chip 從「已接單」→「製作中」
5. 繼續推進到 **COOKING**(60%)→ **PLATING**(85%)→ **READY**(100%)
6. **READY 時手機震動**([300ms, 100ms, 300ms, 100ms, 300ms])+ **閃橘光**
7. 取餐號碼卡變**綠底**,顯示「**請至櫃台取餐**」

### 關鍵 Demo 賣點

- ✅ **WebSocket 即時推送**,延遲 < 200ms
- ✅ 三個事件廣播:`order:statusChanged` / `order:progress` / `order:ready`
- ✅ **手機震動 + 閃光** — 不需叫號廣播、也不需推播通知(降低被使用者關閉的機率)
- ✅ 門市人員**不用學會五個階段名稱**,只看「下一階段」按鈕

## 場景四:會員結帳(60 秒)

> **目標**:展示 VIP 等級制 + 點數回饋,完整展示會員回訪引擎

- ✅ Coupon 自動標記 used,避免重複使用漏洞

## 常見 Q&A(委員可能問的)

**Q: 為什麼驗證碼固定 1234?**
A: Demo 階段簡化。**生產環境會接 SMS gateway**(Twilio / 三竹資訊),邏輯集中在 `backend/src/lib/verifyCode.ts`,替換 OTP provider 即可,前端不需改。

**Q: SQLite 撐得住嗎?**
A: 原型 / MVP / 單店適用。**多門市 + 高併發**請改 PostgreSQL,**Prisma schema 不變**,只需改 `DATABASE_URL` + `prisma migrate dev`。

**Q: 顧客手機一定要裝 APP 嗎?**
A: **不用**。本系統是 PWA,iOS Safari「加入主畫面」後,介面跟原生 APP 一樣;WebSocket / 震動 / 離線 cache 都支援。

**Q: WebSocket 在跨網域 / 反向代理後會通嗎?**
A: 預設支援。需要 Nginx 設定 `Upgrade` / `Connection` 標頭才能 upgrade 成功;Docker / K8s 也都有官方範例。詳見 ARCHITECTURE.md。

**Q: 怎麼防止 Coupon 被截圖外流?**
A: 目前是單次使用(`usedAt` 標記後失效)。**v1.1 會加 QR code 動態驗證**,Coupon 由門市掃碼核銷,不需填電話。

**Q: 廚房人員怎麼知道要做什麼?**
A: 規劃 **v2.x 廚房出餐螢幕(KDS,Kitchen Display System)** — 後端已有 `OrderItem.customizations`(JSON 序列化客製化選擇),可直接渲染為廚房卡片。

**Q: 多門市怎麼處理?**
A: 詳見 ARCHITECTURE.md Roadmap v1.1。預計加 `Store` 模型 + 多店代碼,訂單歸屬到特定門市,中央 dashboard 看全部門市營運。

**Q: 怎麼收費?**
A: 規劃 SaaS 月費制,以「門市數 + 月訂單量」分級。詳細報價見商業計畫書。
